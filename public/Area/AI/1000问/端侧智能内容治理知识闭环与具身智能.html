AI1000问：端侧智能、内容治理、知识闭环与具身智能

本篇迁移 AI 系列剩余 6 张专题卡，覆盖 TinyML、AI 内容创作风险、AI 与个人知识管理闭环、AI 工程自检、具身智能和图灵测试。

11. 为什么有些 AI 应该在 MCU 端运行，而不是全部发到云端？

答案： 端侧推理适合对延迟、隐私、断网可用性和持续云端成本敏感的任务。MCU 端通常适合小模型分类、异常检测、关键词唤醒和简单回归；复杂语言理解和大规模视觉模型更适合 SoC/NPU 或云端。

判断能否部署到 MCU，要同时检查：

  • 模型权重大小（Flash）。
  • 中间激活与工作缓冲区大小（RAM）。
  • 单次推理最坏耗时和任务周期。
  • 功耗、温度、模型精度和失效策略。
flowchart TD
  A[训练：PC / Python] --> B[模型压缩 / 量化]
  B --> C[导出模型]
  C --> D[TFLite Micro / CMSIS-NN 等部署]
  D --> E[MCU 端推理]
  E --> F[实时结果 / 故障监控]
  F --> G[现场数据回流与模型更新]

注意： INT8 量化通常能减少权重存储和计算量，但精度损失、速度提升和 RAM 占用取决于模型结构、算子实现和硬件；不能保证每个模型都“精度几乎不掉”或固定加速倍数。汽车安全相关功能还需要安全分析、独立监控和验证，不能把 AI 输出直接当作唯一安全控制依据。

12. AI 自动生成新闻解析视频，最重要的风险是什么？

答案： 新闻内容的核心要求是事实准确、来源可追溯和语境完整。LLM 可能生成语气流畅但事实错误的摘要，也可能把相关性误写成因果，把评论伪装成事实。

推荐流程：

  1. 先抓取可信来源并保留原文、发布时间和链接。
  2. 让 AI 做结构化提取：谁、何时、何地、发生了什么。
  3. 对事实性陈述逐项绑定来源，来源不足就标注未知。
  4. 评论、归因和争议观点单独标识，不让模型擅自补全。
  5. 人工终审后再配音、生成视频和发布。

还要处理肖像/声音授权、版权、深度伪造、平台规则和不同司法辖区的法律要求。保存 prompt、模型版本、素材授权和生成日期，有助于内容溯源；这不等于自动解决版权归属问题。

flowchart LR
  A[新闻来源] --> B[AI 结构化提取]
  B --> C[逐项事实核验与引用]
  C --> D[人工审校]
  D --> E[脚本 / 配音 / 视频]
  E --> F[发布与更正机制]

13. AI 如何与“堆问题学习法 + 1000问 + 卡片笔记”组成知识管理闭环？

答案： AI 最适合加速问题候选生成、语义检索、归类、摘要、重复识别和跨主题连接；它不能替代亲自实践、证据判断和复盘。

建议把每个问题与答案双向索引：

  • 问题库记录问题状态、答案链接和验证状态。
  • 答案页记录覆盖了哪些问题、用了哪些来源。
  • 实践记录补充真实项目结果、日志和反例。
  • 新问题从实践反馈中产生，再回填问题库。
flowchart TD
  A[1000问：问题地图] --> B[AI 检索 / 分类 / 去重]
  B --> C[答案页：原理与来源]
  C --> D[人工核验与工程实践]
  D --> E[反馈 / 反例 / 新问题]
  E --> A
  C <--> F[卡片笔记与主题索引]

知识质量纪律： AI 答案只是候选材料，必须通过标准文档、实验、项目日志或可靠来源验证后，才能进入长期知识库。

14. AI 项目上线前应检查哪些方面？

答案： 可以按四组检查：

  • 检索与知识：分块是否保留语义边界、overlap 是否合理、检索是否有引用、资料不足是否拒答。
  • 模型与应用：模型是否匹配任务、提示是否明确、是否真的需要微调或 Agent。
  • 工程与部署：延迟、吞吐、内存、成本、监控、回滚和数据闭环是否经过实测。
  • 风险与边界：隐私、版权、偏见、幻觉、越权工具调用和人工审批机制是否明确。

清单不是一套通用合规认证；高风险场景仍需领域专家、法务、安全和质量团队按适用法规与标准评审。

15. 什么是具身智能？它和纯文本/图像 AI 有什么区别？

答案： 具身智能是具有物理或虚拟身体、能够感知环境、形成决策并执行动作，再根据反馈调整行为的智能系统。机器人、自动驾驶车辆和机械臂是典型载体。

核心闭环为感知 → 决策 → 行动 → 反馈。难点包括连续带噪声的传感数据、实时控制、物理约束、安全风险、真实数据采集和 Sim-to-Real 迁移。

flowchart LR
  A[摄像头 / 雷达 / 力矩 / 触觉] --> B[感知与状态估计]
  B --> C[任务理解与规划]
  C --> D[运动控制]
  D --> E[机器人 / 车辆 / 机械臂]
  E --> F[真实环境反馈]
  F --> A

VLA（Vision-Language-Action）模型尝试把视觉、语言指令和动作表示连接起来；但高层模型仍需低层实时控制、安全监控和故障降级共同保障。仿真训练也必须通过真实设备验证。

16. 图灵测试怎么做？它能证明机器真正理解了吗？

答案： 图灵在 1950 年提出“模仿游戏”作为讨论机器智能的思想实验。常见简化版本中，询问者通过文本分别与人和机器对话，判断哪一个是机器。如果询问者难以稳定区分，就说明机器在该测试条件下表现出类似人类的对话行为。

测试设计要控制身份线索、对话时长和题目范围，最好让多个询问者独立判断，并报告样本数和置信区间。图灵测试测量的是特定条件下的语言行为，不足以单独证明意识、真实理解、可靠推理或现实世界能力。

重要区分： “能骗过人类”与“理解世界”不是同一个命题。中文房间等思想实验正是对这种推论提出质疑。
