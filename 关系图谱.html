知识关系图谱

这里把笔记之间的主题关系、学习依赖和实践路径放在同一张地图里。图谱不是目录的替代品：目录负责定位，关系图谱负责理解“哪些知识互相支撑、可以沿什么路径继续学习”。

如何使用

  • 从下方的主题节点进入对应索引页，再沿着页面中的双向链接深入。
  • 在任意笔记右侧查看局部关系图；在全局图中展开全部可索引笔记的关系网络。
  • 新增笔记时，尽量链接到已有概念、上游基础、工程案例或相反观点，不要只添加标签。

2. 主题入口与关键连接

  • 数字花园入口：PARA 的总入口；连接 长期领域、项目、资源 与 存档。
  • 知识管理：连接 知识管理原则、日常工作流、渐进阅读、微信读书到永久笔记 和 数字花园发布。
  • 电子与嵌入式：以 电子基础、C 语言、MCU、RTOS、操作系统、计算机网络 为基础，向汽车电子工程实践延伸。
  • AUTOSAR 项目：连接 核心理念、软件架构、方法论、标准与规范、规范模块 和工程实践专题。
  • 阅读资源：包括 微信读书、教育资料、提问的智慧、GitHub、RSS 与影视资料。外部摘录应继续加工成自己的观点，并链接到对应领域或项目。

5. 提问与工程协作链

提问的智慧 将知识管理延伸到问题诊断与团队协作：先把异常转化为可验证的问题，再通过证据和实验缩小范围，最后将解决方案沉淀为可检索知识。

flowchart TD
    ISSUE["工程异常 / 学习疑问"] --> GOAL["明确目标与预期"]
    GOAL --> FACT["收集环境、日志和复现证据"]
    FACT --> SEARCH["检索文档、FAQ 与历史讨论"]
    SEARCH --> TEST["最小化实验与定位"]
    TEST --> ASK["结构化提问与协作"]
    ASK --> VERIFY["验证答案与修复"]
    VERIFY --> RETRO["复盘并更新文档 / FAQ"]
    RETRO --> KB["知识库与团队经验"]
    KB --> ISSUE

推荐将 提问的智慧 与 知识管理工作流 配合使用：前者解决“如何把问题说清楚”，后者解决“如何把答案变成可复用知识”。

6. 当前图谱盘点与维护规则

基于仓库当前生成的 Quartz 内容索引，页面数与链接关系会随笔记更新、链接解析和标签变化而变化；应以最新构建索引为准，不将历史统计视为固定值。

  • 主要枢纽：Area 总览、AUTOSAR 规范模块索引、Classic Platform、AUTOSAR 总览、RTE。
  • 需要优先补强的连接：资源书目到永久笔记、计算机基础到汽车电子、AUTOSAR 规范到工程实践、AI/智能体到具体项目案例。
  • 孤立页面检查：构建索引中有少量页面没有解析到其他页面的链接。新增或整理笔记时，应优先补充至少一个有语义的关联；若确实独立，写明原因。
  • 避免无意义连边：不要为了增加连线而堆砌链接。链接最好能表达“前置知识”“组成部分”“实践案例”“相反观点”“应用场景”或“来源”中的一种关系。
  • 标签不是关系的全部：标签适合聚类，双向链接表达具体语义，索引页负责学习顺序，三者应互相补充。
