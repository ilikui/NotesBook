# **单片机驱动开发指南与开发框架

> 来源：Flomo 原始笔记｜[查看原笔记](https://v.flomoapp.com/mine/?memo_id=MjUxODA3Mzc2)｜迁移日期：2026-10-31

▎ **单片机驱动开发指南与开发框架**

▎ **驱动是什么**<br> 驱动 = 硬件和应用之间的中间层——上层不管寄存器，下层不管业务。「UART 轮询 → 中断 → 环形缓冲区」就是最典型的驱动演进路径。

▎ **三层模型（对应 AUTOSAR MCAL 思路）**

1. 硬件抽象层：寄存器读写 \+ 位操作宏——芯片相关

2. 外设驱动层：协议 / 时序（UART 帧、SPI 时序、I2C 时序）——外设相关

3. 设备接口层：给应用的标准 API——应用相关<br> → 对应 AUTOSAR：MCAL → ECU 抽象 → 服务层


▎ **开发 7 步**

1. 读 datasheet：寄存器地图、时序图、电气参数——先懂硬件再写码

2. 定义接口：应用要什么 API，别被寄存器绑架

3. 寄存器封装：SET\_BIT / CLR\_BIT 位操作宏

4. 底层实现：初始化 \+ 收发，先轮询跑通

5. 性能升级：轮询 → 中断 → DMA / 环形缓冲区

6. 可移植隔离：芯片相关收进一层（函数指针表 / 条件编译）

7. 回环测试：loopback 验证收发，再上总线


▎ **框架选型**

- 裸机自写 HAL：轻量、可控

- STM32：HAL 库（全但慢）/ LL 库（轻但底层）/ CubeMX 生成

- 生态型：libopencm3、ChibiOS HAL、Zephyr 驱动框架

- 汽车：AUTOSAR MCAL（MCU / Port / Dio / Spi / I2c / Uart）

- 依据：可控性 vs 效率 vs 生态


▎ **六个坑**

1. 不读时序图就写代码

2. 轮询当最终版（不上中断 / DMA）

3. 缓冲区大小拍脑袋（按波特率 × 时间算）

4. 多字节寄存器读撕裂

5. 硬编码芯片型号（不可移植）

6. 不做回环测试直接上总线


▎ **一句话**：驱动开发 = 三层模型 \+ 7 步流程——先接口后寄存器、先轮询后中断、先回环后总线；框架选型看你要可控（自写 HAL）、要效率（LL）还是要生态（AUTOSAR MCAL）。
