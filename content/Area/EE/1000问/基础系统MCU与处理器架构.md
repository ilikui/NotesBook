# 嵌入式1000问：系统基础、MCU与处理器架构

本篇迁移嵌入式 1000 问第一批 3 张完整问答卡，覆盖嵌入式系统的本质、MCU/MPU 选型和冯诺依曼/哈佛结构。

## 1. 嵌入式系统和通用计算机系统最本质的区别是什么？

**答案：** 关键差异是系统是否围绕特定设备功能和应用任务进行软硬件协同设计。嵌入式系统通常为确定的功能集合做资源、功耗、成本、实时性和可靠性取舍；通用计算机面向更广泛、可变的任务。

这种目标差异会影响：

- 资源预算：RAM、Flash、CPU、功耗和 BOM 成本。
- 软件形态：裸机、RTOS、Linux 或异构 OS。
- 实时性：控制闭环、响应时间和抖动约束。
- 生命周期：长期运行、远程升级、故障自恢复和安全策略。
- 开发流程：软硬件联合调试、寄存器、时钟、电源和上电时序。

**纠正一个常见误区：** 嵌入式不等于低性能，也不等于没有操作系统。汽车域控制器、智能座舱和边缘 AI SoC 仍属于嵌入式系统；判断标准是它是否作为更大设备/系统的一部分，为特定应用目标协同设计。

  A --> C[软件形态：裸机 / RTOS / Linux]
  B --> D[资源、功耗、成本与外设]
  C --> E[实时性、功能与升级]
  D --> F[软硬件协同验证]

## 2. MCU 和 MPU 的核心区别是什么？什么时候选谁？

**答案：** MCU 通常把 CPU、片上 Flash、SRAM 和外设集成在一颗芯片中，适合控制类、低功耗、成本敏感和实时性要求明确的任务。MPU 通常以处理器核心为主，需要外接 DDR/存储和更复杂的电源、启动与外围电路，适合运行 Linux、图形界面、网络服务和复杂应用。

| 维度 | MCU | MPU |
|---|---|---|
| 集成度 | 通常集成 Flash、SRAM 和外设 | 通常需要外接 DDR/存储 |
| 软件 | 裸机、RTOS，部分可跑轻量 OS | Linux、QNX、Android 等 |
| 实时控制 | 常见低延迟、可预测控制场景 | 需结合实时 OS、隔离核或协处理器设计 |
| 系统复杂度 | 启动链与外围相对简单 | BootROM、Bootloader、内核和用户空间 |
| 成本与功耗 | 常适合低成本、低功耗 | 通常外围更复杂、功耗更高 |

**选型原则：**

- 选 MCU：电机控制、PWM、传感器采样、车身 ECU、低功耗控制、固定功能。
- 选 MPU：复杂网络、文件系统、图形界面、大内存、高算力和丰富软件生态。
- 选异构 SoC/组合方案：既需要 Linux 应用处理，又需要独立实时控制和安全隔离时。

**术语提醒：** MPU 也可能指 Memory Protection Unit（内存保护单元），这是另一个概念，不要与 Microprocessor Unit（微处理器）混淆。

~~~~mermaid
flowchart TD
  A[需求分析] --> B{是否需要 Linux / 大内存 / 复杂应用？}
  B -->|否| C{是否强调低功耗与实时控制？}
  C -->|是| D[MCU]
  C -->|否| E[评估 MCU / MPU / SoC]
  B -->|是| F{是否还需硬实时控制？}
  F -->|是| G[异构 SoC：A 核 + M 核 / 独立 MCU]
  F -->|否| H[MPU]
~~~~

## 3. 冯诺依曼结构和哈佛结构有什么区别？STM32 属于哪一种？

**答案：**

- 冯诺依曼结构：指令和数据共享存储空间及访问通路，结构简单，但取指和取数可能竞争同一通路。
- 哈佛结构：指令和数据存储/通路分离，允许取指与数据访问并行，结构相对复杂。
- 改进型哈佛结构：保留独立指令/数据通路的性能优势，同时提供统一或较统一的地址映射。

STM32 使用的 Cortex-M 内核通常采用改进型哈佛组织：内核具有 I-Code、D-Code 和 System 等不同访问通路，但对软件呈现统一的内存映射地址空间。具体总线、存储映射和缓存行为应以所用 Cortex-M 内核与 STM32 型号参考手册为准。

~~~~mermaid
flowchart TB
  subgraph VN[冯诺依曼结构]
    VCPU[CPU] <--> VBUS[共享总线]
    VBUS <--> VM[指令与数据共享存储]
  end
  subgraph H[哈佛结构]
    HCPU[CPU] --> IBUS[指令总线]
    HCPU --> DBUS[数据总线]
    IBUS --> IM[程序存储]
    DBUS --> DM[数据存储]
  end
  subgraph MH[改进型哈佛：典型 Cortex-M]
    MCPU[CPU] --> IC[I-Code]
    MCPU --> DC[D-Code]
    MCPU --> SYS[System Bus]
    IC --> MEM[统一地址映射]
    DC --> MEM
    SYS --> MEM
  end
~~~~

**对编程的影响：** 在部分 Harvard MCU 上，程序存储区与数据存储区访问方式不同，常量读取可能需要平台专用机制；在 Cortex-M 等统一内存映射平台上，普通 C 代码通常不需要显式区分，但仍需理解 Flash、SRAM、外设区和总线属性。

## 工程验证清单

- 先列出实时周期、最坏响应时间、功耗、成本、存储容量和安全等级需求。
- 查 MCU/MPU 数据手册，确认片上 Flash/RAM、MMU/MPU、DMA、总线和外设。
- 对 Cortex-M 项目核对具体内核型号、总线矩阵、存储映射和缓存/TCM 配置。
- 在目标硬件上测量启动时间、中断延迟、任务抖动和功耗，不以芯片主频替代系统性能验证。
