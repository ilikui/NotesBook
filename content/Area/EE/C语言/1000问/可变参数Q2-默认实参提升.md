**C语言 1000问 · 可变参数Q2：为什么取参数时要用「提升后」的类型？默认实参提升（default argument promotions）是怎么回事？**

▎ 五大学习法：费曼学习法——把「实参提升」讲透

**什么是默认实参提升**

- 在「没有原型（旧式声明、可变参数）」的调用里，C 会把某些小类型自动提升成更大类型再传：
  - char、short（含 signed / unsigned 变体）、int 位域 → int（int 装得下时），装不下则 unsigned int。
  - float → double。
  - 枚举 → int。
- 这就是「默认实参提升」（default argument promotions）。

**为什么会有这个规则**

- 历史：早期 C 没有原型，编译器只能按「默认类型」传参。
- 硬件：寄存器 / 栈槽通常按机器字对齐，传一个 char 也占一个字，不如统一按 int 传。
- 结果：函数（尤其可变参数）收到的实参类型，和你写的字面类型可能不一样。

**为什么 va\_arg 要用提升后的类型**

- va\_arg(ap, type) 承诺「下一个参数就是 type 类型」。
- 但实参已被提升：你传 char 'a'，栈上其实是 int；传 float 1.0f，其实是 double。
- 若写 va\_arg(ap, char) 或 va\_arg(ap, float)，类型对不上——未定义行为（读到错值或错位地址）。
- 正确：va\_arg(ap, int) 取原来的 char / short；va\_arg(ap, double) 取原来的 float。

**例子**

- 错误：va\_arg(ap, char) 取 char 实参 → 错位。
- 正确：va\_arg(ap, int)；float 实参则 va\_arg(ap, double)。
- printf 里同理：%f 对应 double（不是 float），%c 对应 int（不是 char）——这就是「提升」的体现。

**和「整型提升」的区别**

- 默认实参提升：传参时把窄类型提升到 int / double。
- 整型提升（integer promotion）：表达式求值时，把比 int 小的整型提升为 int 再运算。
- 两者相关但场景不同：一个在函数调用，一个在算术运算。

**几个易错点**

- 传 char / short 给 va\_arg 必须用 int。
- 有了原型（prototype），编译器做的是「实参转换」而非默认提升（如原型声明 int f(float)，传 float 就按 float 传，不升成 double）。
- 所以可变参数最容易踩的就是「提升导致的类型不匹配」。

一句话：默认实参提升是「小类型自动升级」——char / short → int、float → double；因为参数入栈前就被提升了，va\_arg 必须按提升后的类型取，否则读错值或错位，这就是可变参数最常见的坑。
