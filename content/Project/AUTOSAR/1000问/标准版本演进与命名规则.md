AUTOSAR 版本演进：命名从 R4.x 切到「年份-月份」

先厘清命名分水岭：R4.0～R4.3 是老式 R4.x 命名；大约从 R4.4 起，AUTOSAR 改成「发布年-月」命名（R19-11 这一档大致对应 R4.4）。所以 R20-11、R21-11 不是全新系列，是 R4.x 的延续，只是换了名字。

各版本最有代表性的变化（大致脉络）：

- R4.0：Classic 平台分水岭。方法论与 SW-C 接口全面标准化，OS 规范化，把 R3 时代的遗留推到体系化，很多厂商从这版开始真正量产落地。
- R4.1：多核支持起步（多核 OS + 早期 IOC），功能安全的接口与模块补充。
- R4.2：多核与通信栈增强，CAN FD 进标准；信息安全相关模块开始出现。
- R4.3：新增一批模块——SecOC、Crypto Stack、全局时间同步（StbM）、E2E 细化；Adaptive 平台雏形出现。也是命名转「年份-月」的时间点。
- R20-11：在 R4.4/R19-11 基础上完善，以规范修订、配置属性增补为主，模块接口无剧烈变化。
- R21-11：进一步修订与增补，多为细化与勘误级别。

实际影响最大的判断：对 BSW 配置与生成代码影响大（模块接口、配置属性会变），对应用层 SW-C 影响相对小（RTE 接口大体稳定）。跨版本迁移最头疼的往往是工具适配 + 仲裁/验证行为的变化，而不是接口本身推倒重来。

（方向性判断为主，某版本具体哪个模块先出现可能有出入。）

## 版本编号的准确解释（官方 Release 文档核对）

AUTOSAR 同时存在两套容易混淆的编号：

- **Platform Release**：采用 Ryy-mm，例如 R19-11、R20-11；yy/mm 表示发布年份和月份。
- **Internal Release Number**：Classic BSW 模块规范中常见的 R4.x.y 编号，用于模块规范的内部版本演进。它不是简单把 Ryy-mm 字符串换个写法。

| 平台发布 | 内部版本/关联信息 | 说明 |
|---|---|---|
| Classic R4.4.0 | Schema AUTOSAR_00046 | 2018-10 发布 |
| R19-11 | Internal R4.5.0；Schema AUTOSAR_00048 | R19-11 supersedes Classic R4.4.0 |
| R20-11 | Internal R4.6.0；Schema AUTOSAR_00049 | 官方 Release Overview 明确标注 R20-11 是 minor release |

因此，“R4.4 改名成 R19-11”只能作为时间线上的粗略说法，不应理解为两个编号完全等价；对工具兼容性，必须同时核对平台发布、内部规范版本、ARXML Schema、模块 SWS 和工具支持矩阵。

**截至 2026-11-01：** AUTOSAR 官网 Classic Platform 页面列出的当前发布版为 R25-11；R26-11 发布活动安排在 2026-12-03，尚不能把它写成当前已发布版本。项目落地仍以 OEM 指定 Release 和供应商工具支持范围为准。
