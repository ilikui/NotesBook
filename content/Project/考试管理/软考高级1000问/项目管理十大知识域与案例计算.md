# 项目管理师1000问：十大知识域、项目治理与案例计算

本篇迁移信息系统项目管理师题库第二批 25 道问答，覆盖信息化规划、整体/范围/进度/成本/质量、人力、沟通、风险、采购、干系人、法律合规和案例分析。项目管理术语按通用知识体系整理，具体考试版本与法规条款以当年官方材料为准。

## 一、信息化与项目启动

### Q21. 国家信息化体系常说的“六要素”是什么？

**答案：** 常见概括包括信息资源、信息网络、信息技术应用、信息技术和产业、信息化人才、信息化法规政策。记忆时要理解相互关系：信息资源是重要核心，网络是基础设施，技术应用把能力转化为业务价值，人才和法规提供组织与制度保障。不同教材对表述和排序可能略有差异。

### Q22. 电子政务和电子商务的典型模式怎样区分？

**答案：** 电子政务常见 G2G（政府间）、G2B（政府与企业）、G2C（政府与公众）、G2E（政府与公务员）；电子商务常见 B2B、B2C、C2C 等。判断题目时先看交易/服务双方的主体身份，再识别服务对象和业务目标。

### Q23. CSF、SST 和 BSP 是什么信息化规划方法？

**答案：**

- CSF（关键成功因素法）：识别决定组织成功的关键因素，再确定信息系统支持重点。
- SST（战略目标集转化法）：把组织战略目标转换成信息系统目标。
- BSP（企业系统规划法）：从业务过程和数据资源出发规划企业信息系统。

方法不是互斥工具，可结合组织战略、业务流程和数据架构使用。

## 二、整体与范围管理

### Q24. 项目章程和项目范围说明书有什么区别？

**答案：** 项目章程正式授权项目启动并赋予项目经理相应职责；范围说明书进一步描述项目和产品范围、主要交付物、验收标准与边界。章程回答“为什么启动、谁负责”，范围说明书回答“做什么、不做什么、怎样验收”。

### Q25. 整体变更控制为什么需要 CCB？

**答案：** CCB（变更控制委员会）或授权变更责任人评估变更对范围、进度、成本、质量、资源、风险和合同的影响，决定批准、拒绝或延期。小型项目可以有简化流程，但必须明确决策权限、记录和基线更新，不能让单个开发人员私自改变基线。

### Q26. WBS 的 100% 原则是什么意思？

**答案：** WBS 的下层工作应完整覆盖上层工作范围，既不能遗漏工作，也不能重复计算。分解到可估算、可分配责任、可跟踪和可验收的工作包即可；分解过细会增加管理成本，过粗则难以估算和控制。

### Q27. Scope Creep 和 Gold Plating 有什么区别？

**答案：** Scope Creep 是未经充分控制的范围扩张，可能来自客户或内部需求变化；Gold Plating 是团队主动增加未要求的功能或质量特性。二者都会带来成本、进度和验证风险。新增内容应走需求/变更评估，而不是“做得越多越好”。

### Q28. 为什么 WBS 元素要对应可验证的交付物？

**答案：** 可交付物让工作范围有明确结果和验收依据。若 WBS 只有“开发模块”“优化系统”这类模糊活动，难以判断完成标准、估算工期和确认责任。应为工作包定义输出、完成条件和责任人。

## 三、进度管理

### Q29. 关键路径、总浮动时间和自由浮动时间怎样计算？

**答案：** 关键路径是网络计划中决定项目最短工期的最长路径。前推计算 ES/EF，后推计算 LS/LF：

- 总浮动 TF = LS−ES = LF−EF。
- 自由浮动 FF = min(后续活动 ES)−当前活动 EF。

总浮动为零的活动通常位于关键路径；若存在多个关键路径，任一关键路径延误都可能影响项目总工期。

### Q30. PERT 三点估算的期望工期和标准差如何计算？

**答案：** 乐观时间 O、最可能时间 M、悲观时间 P：

~~~~text
TE = (O + 4M + P) / 6
σ  = (P - O) / 6
Variance = σ²
~~~~

这是基于 Beta 分布近似的估算方法。将多个活动的方差合并时，需确认独立性等假设；“±2σ 约 95%”是正态近似，不应对所有项目估算无条件套用。

### Q31. Crashing 和 Fast Tracking 有什么区别？

**答案：** Crashing（赶工）增加资源或成本以缩短关键活动工期；Fast Tracking（快速跟进）把原本串行的活动部分并行，通常增加返工和协调风险。两种方法都应优先作用于关键路径，并比较缩短工期的边际成本与风险。

## 四、成本管理

### Q32. EVM 的 PV、EV、AC、SV、CV、SPI、CPI 分别是什么？

**答案：**

- PV：计划价值，按计划截至当前应完成工作的预算价值。
- EV：挣值，实际完成工作对应的预算价值。
- AC：实际成本。
- SV=EV−PV：进度偏差。
- CV=EV−AC：成本偏差。
- SPI=EV/PV：进度绩效指数。
- CPI=EV/AC：成本绩效指数。

SV/CV 为负通常表示落后/超支；SPI/CPI 小于 1 通常表示进度/成本效率低于计划。

### Q33. EAC 为什么有不同计算公式？

**答案：** EAC（完工估算）取决于对未来工作的假设：

- 若当前偏差是偶发的，未来按预算效率完成：EAC=AC+(BAC−EV)。
- 若当前成本效率持续：EAC=AC+(BAC−EV)/CPI。
- 若成本与进度效率共同影响剩余工作：可用 EAC=AC+(BAC−EV)/(CPI×SPI) 作为相应假设下的估算。

公式不是随意选择，必须先说明未来绩效假设。

## 五、质量管理

### Q34. QA 和 QC 有什么区别？

**答案：** QA（质量保证）关注过程是否适当、过程是否被执行和持续改进；QC（质量控制）关注具体交付物是否满足要求。代码评审、过程审计、测试计划属于质量保证/过程管理的一部分；单元测试、集成测试、检验和测量属于质量控制活动。两者互补，不能只写“增加测试”就代表完整质量管理。

### Q35. PDCA 和七种质量工具如何用于项目质量改进？

**答案：** PDCA 是 Plan-Do-Check-Act 循环：计划改进、实施、检查结果、固化或调整。常见质量工具包括因果图、流程图、检查表、帕累托图、直方图、散点图和控制图。工具要对应问题：分析根因可用鱼骨图，识别主要类别可用帕累托图，监控过程稳定性可用控制图。

## 六、人力与沟通管理

### Q36. 团队形成、震荡、规范、执行和解散五阶段是什么？

**答案：** 这是 Tuckman 团队发展模型：Forming、Storming、Norming、Performing、Adjourning。阶段不是每个团队都严格按固定顺序、固定时间经历；项目经理要根据团队成熟度调整目标澄清、冲突处理、协作规则和授权方式。

### Q37. 马斯洛需求层次和赫茨伯格双因素理论怎样用于团队激励？

**答案：** 马斯洛模型把需求分为生理、安全、归属、尊重和自我实现等层次；赫茨伯格区分保健因素（薪酬、环境、制度等，缺失会引起不满）与激励因素（成就、认可、成长等）。这些理论可帮助思考激励方案，但不是对每个人行为的绝对预测，应结合个体差异和实际反馈。

### Q38. 沟通渠道数为什么是 N(N−1)/2？

**答案：** 若 N 个成员之间每两人都可能直接沟通，潜在双向沟通关系数为组合数 C(N,2)=N(N−1)/2。10 人对应 45 条，20 人对应 190 条。它衡量潜在连接数量，不等于实际沟通量或沟通效率；可通过角色、例会、接口文档和决策机制降低无效沟通。

### Q39. 为什么沟通中需要“回读确认”？

**答案：** 信息要经历编码、传递、接收和解码；发送者认为表达清楚，不代表接收者理解一致。关键需求、接口、风险和变更应让接收方复述理解、确认版本和验收标准，并保留记录，减少“以为说过了”的隐性误差。

## 七、风险、采购与干系人管理

### Q40. 风险概率×影响矩阵有什么作用和局限？

**答案：** 风险矩阵用概率和影响对风险排序，帮助团队决定优先处理事项。它适合定性分级，不等于精确风险价值；不同风险的影响维度可能包括安全、成本、进度、质量和声誉，不能简单用一个数字完全表达。

### Q41. 风险回避、转移、减轻和接受分别是什么？

**答案：**

- 回避：改变计划，使威胁不再发生或不再影响目标。
- 转移：通过保险、合同或外包转移部分财务后果/责任，但不一定转移全部风险。
- 减轻：降低发生概率或影响。
- 接受：主动接受或被动接受，并按需要准备应急储备。

机会风险也有利用、增强、分享和接受等策略，考试题要区分威胁和机会。

### Q42. 固定总价、成本补偿和工料合同的风险分配有什么区别？

**答案：** 固定总价合同通常把较多成本超支风险放在卖方；成本补偿合同通常把更多成本风险放在买方；工料合同按工时和材料计价，风险分担取决于上限、费率和管理条款。合同选择要看需求确定性、成本可估算程度和双方风险承受能力。

### Q43. 权力/利益矩阵怎样管理干系人？

**答案：**

- 高权力、高利益：重点管理、持续参与。
- 高权力、低利益：保持满意，关注重大变化。
- 低权力、高利益：及时告知并听取反馈。
- 低权力、低利益：适度监督。

矩阵是动态工具，项目阶段变化后干系人的权力、利益和态度也可能变化，应定期更新。

## 八、法规、案例与论文

### Q44. 招投标、知识产权和网络安全等级保护题怎样避免背错过期数字？

**答案：** 先掌握法律原则和制度框架，再核对当年有效法规、配套办法和考试教材。招标范围/金额门槛、评标程序、网络安全等级保护测评周期和软件著作权归属都可能受法规版本、合同和项目类型影响，不能把旧笔记中的某个数字当成永远有效的通用规则。

软件职务作品的权利归属也不能简单说“员工在公司写的软件一律归公司”；应根据作品类型、法律规定、合同约定和实际开发关系判断。

### Q45. 案例分析“找错题”怎样作答更有说服力？

**答案：** 使用“理论要求—题干证据—问题判断—改进措施”四步：

1. 写明该管理过程/技术活动的正确要求。
2. 引用题干中的具体事实。
3. 说明事实与要求的差距。
4. 给出可执行的纠正和预防措施。

避免只写“沟通不好”“风险管理不足”这类没有证据的结论。

flowchart TD
  A[题干事实] --> B[对应知识领域]
  B --> C[理论要求]
  C --> D[逐条对照]
  D --> E[问题与影响]
  E --> F[纠正措施 / 预防措施]
~~~~
