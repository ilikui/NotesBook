自动驾驶1000问：分级、感知与多传感器融合

本篇迁移自动驾驶系列第一批 10 张已回答卡片，覆盖 SAE 自动化分级、感知—决策—执行链、EE 架构演进、多传感器盲区、雷达价值、雨天冗余、外参标定、时间同步、融合层级和 GNSS 退化定位。

1. L2 和 L3 的本质分界在哪里？

答案： 按 SAE J3016 的术语，L2 属于部分驾驶自动化，系统可同时执行横向和纵向动态驾驶任务，但驾驶员必须持续监督环境并承担后备责任。L3 属于有条件驾驶自动化，在系统处于其设计运行域（ODD）且功能可用时，由自动驾驶系统执行动态驾驶任务；用户不必持续监督环境，但必须在系统发出接管请求时及时响应。

关键区别是持续监督责任与后备角色，而不是单纯看车辆是否能自动转向和加减速。

重要修正： SAE 分级描述自动化功能和驾驶任务角色，不直接裁定事故法律责任。责任如何分配取决于所在司法辖区的法律、产品责任规则、使用条件和事故事实，不能简单说“L3 法律责任全部转给主机厂”。

2. 感知、决策规划、执行三环各自最容易出什么问题？

答案：

  • 感知：开放世界长尾、遮挡、恶劣天气、传感器物理局限、误检漏检。
  • 决策规划：交通参与者意图不确定、交互博弈、规则覆盖不足、舒适性与安全性取舍。
  • 执行：制动/转向/驱动硬件失效、执行延迟、冗余切换失败和控制精度不足。

感知往往面对最开放的输入空间，因此长尾场景是难点；但不能笼统断言所有事故都来自感知。真实系统风险取决于 ODD、系统架构、验证覆盖和安全机制。

flowchart LR
  A[环境与传感器] --> B[感知：目标 / 车道 / 可行驶区]
  B --> C[决策规划：行为 / 路径 / 轨迹]
  C --> D[执行：转向 / 制动 / 驱动]
  D --> E[车辆运动]
  E --> A
  B -.不确定性.-> F[安全监控与降级]
  C -.约束.-> F
  D -.反馈.-> F

3. 为什么汽车电子架构从分布式 ECU 向中央计算与区域控制演进？

答案： 这是算力、带宽、软件迭代、成本和线束共同驱动的系统性变化：

  1. 自动驾驶与智能座舱增加集中算力需求。
  2. 软件定义汽车和 OTA 需要统一软件平台、部署与升级管理。
  3. 摄像头、雷达和激光雷达数据对通信带宽提出更高要求。
  4. 区域控制器按物理位置汇聚 I/O，可缩短线束、降低重量和装配复杂度。
  5. 软硬件解耦、服务化通信和跨域协同提高软件复用空间。
flowchart LR
  A[分布式 ECU] --> B[域集中架构]
  B --> C[中央计算 + 区域控制 Zonal]
  A --- A1[功能分散 / ECU 众多]
  B --- B1[动力 / 底盘 / 座舱 / 智驾域]
  C --- C1[中央算力平台]
  C --- C2[区域控制器与高速骨干网]

4. 摄像头、毫米波雷达、激光雷达、超声波分别有什么盲区？

答案：

传感器优势主要局限
摄像头语义丰富，能识别颜色、标志、车道线深度估计、暗光/逆光、雨雪遮挡和眩光
毫米波雷达测距测速、恶劣天气适应性较好角分辨率和目标分类能力受限，易受多径等影响
激光雷达高精度三维几何信息雨雾雪和污渍会影响点云质量，成本与布置也有约束
超声波近距离、低速泊车成本低探测距离短、方向性和材料反射特性限制

融合的意义不是让某一种传感器变得完美，而是利用不同物理原理的互补性，并识别它们共同失效的边界。

5. 毫米波雷达分类能力有限，为什么仍然重要？

答案： 毫米波雷达能直接提供距离和相对速度，在雨、雾、尘等能见度下降时仍具有价值；对 ACC、AEB 等功能，目标距离、相对速度和碰撞时间是关键输入。

摄像头通常补充语义分类，雷达提供稳定的距离/速度信息，融合模块综合判断。毫米波并非在所有天气和目标上都“不会受影响”，它也存在分辨率、遮挡、多径和虚警问题。

6. 激光雷达在雨天受影响时，冗余靠什么？

答案： 雨天冗余依赖异构传感器、融合策略和 ODD 安全边界，而不是寻找一种绝对不受天气影响的传感器。

  • 毫米波雷达提供距离与速度信息。
  • 摄像头在可用条件下补充语义信息。
  • 融合算法根据传感器健康状态和置信度调整权重。
  • 当感知质量不足以满足安全目标时，系统应降级、减速、请求接管或退出当前 ODD。

注意： “激光怕雨”不是二元开关。影响程度与降雨强度、波长、安装位置、传感器设计、污染状态和算法处理有关。

7. 外参标定错误会怎样沿系统传播？

答案： 外参描述传感器之间、以及传感器与车辆坐标系之间的相对位置和姿态。外参偏差会让同一目标在不同传感器坐标系中的投影不一致，导致关联错误、位置/速度估计偏差，并进一步影响定位、规划和控制。

flowchart TD
  A[外参平移 / 旋转误差] --> B[坐标变换偏差]
  B --> C[目标投影与关联错误]
  C --> D[融合位置 / 速度偏差]
  D --> E[决策与轨迹规划偏差]
  E --> F[制动 / 转向风险]
  G[在线标定监控与一致性检查] -.检测.-> B

验证方法： 使用标定板/场景特征做离线标定；上线后检查跨传感器目标重合度、静态结构对齐误差和标定参数漂移。外参错误可能是静默的系统性误差，不能只靠单次传感器自检判断。

8. 摄像头 30fps、激光雷达 10Hz、雷达 20Hz，怎样做时间对齐？

答案： 不同传感器必须先共享可比较的时间基准，再为数据打上采集时间戳，最后把异步观测转换到同一参考时刻。

  1. 时间同步：使用统一时钟源或同步协议，控制时钟偏差。
  2. 时间戳：优先记录采集时刻，而不是数据到达处理器的时刻。
  3. 对齐与补偿：按时间窗口匹配观测，并依据车辆/目标运动模型进行运动补偿。
flowchart LR
  A[统一时钟] --> B[各传感器采集时间戳]
  B --> C[选择融合参考时刻]
  C --> D[时间窗口匹配]
  D --> E[运动补偿 / 插值]
  E --> F[同一时刻的融合观测]

若车辆速度为 30 m/s，10 ms 时间偏差就对应约 0.3 m 的车辆位移，因此高速场景下时间同步误差不可忽略。AUTOSAR 项目可涉及 StbM 等时间基础设施，但实际传感器同步链路还要看硬件、网络和平台架构。

9. 前融合、特征级融合、后融合分别适合什么场景？

答案：

  • 前融合/数据级融合：在原始数据层对齐并融合，信息保留多，但对标定、同步、数据带宽和算力要求高。
  • 特征级融合：各传感器先提取特征，再在特征空间融合；BEV 感知是常见路线之一，兼顾信息量与工程复杂度。
  • 后融合/目标级融合：各传感器独立输出目标，再进行关联和跟踪；模块边界清晰、易于分系统验证，但会丢失部分原始信息。

没有一种融合层级在所有指标上都最优。量产方案通常按传感器组合、算力预算、功能安全、验证能力和 ODD 做取舍。

10. 高精地图和导航地图有什么本质区别？

答案： 导航地图主要服务于道路级路径规划和驾驶员导航，通常表达道路拓扑、道路等级、限速和 POI；高精地图面向机器驾驶，可能包含车道线、曲率、坡度、停止线、交通标志和信号灯等更细粒度的车道级语义与几何信息。

两者在精度、数据内容、更新频率和使用场景上不同。具体精度等级并非所有地图产品都固定为某个数值，必须看地图规范、产品定义和定位误差指标。高精地图成本与更新压力推动轻地图/无图方案发展，但道路拓扑先验仍可能保留。

flowchart LR
  A[导航地图] --> B[道路级拓扑 / 路线规划 / 人类导航]
  C[高精地图] --> D[车道级几何 / 语义 / 定位先验]
  B --> E[全局 Route]
  D --> F[局部感知与规划辅助]

11. GNSS/GPS 丢星时，车辆定位靠什么维持？

答案： 绝对定位信号暂时不可用时，系统可通过惯性测量、轮速、车辆运动模型和环境感知继续估计相对运动，并在可用时由视觉/激光/地图特征提供校正。

  • IMU：高频、连续，但积分误差随时间漂移。
  • 轮速与转向角：可提供车辆运动约束，但会受打滑、轮胎半径和模型误差影响。
  • 视觉里程计：利用图像特征估计运动。
  • 激光雷达定位：通过点云与地图/局部地图匹配。
  • 多传感器融合：常使用 EKF/ESKF 等估计框架融合不同频率和不确定度的观测。
flowchart TD
  I[IMU] --> F[状态估计 / EKF]
  W[轮速与转向角] --> F
  V[视觉里程计] --> F
  L[激光雷达匹配] --> F
  G[GNSS / RTK 可用时] --> F
  F --> P[车辆位置 / 姿态 / 速度]
  P --> C[定位置信度与降级判断]

验证与工程实践清单

  • 分级功能：明确 ODD、接管请求、驾驶员监控和法规适用范围。
  • 传感器：覆盖逆光、夜间、雨雾、遮挡、反射和静止目标。
  • 标定：做静态标定、动态一致性检查和温度/振动后的漂移监控。
  • 时间同步：测量时钟偏差、采集时间戳误差、端到端延迟和抖动。
  • 融合：注入单传感器失效、虚警、漏检和时间戳异常，验证降级策略。
  • 定位：覆盖隧道、地库、城市峡谷、轮速打滑和地图缺失场景。
