自动驾驶1000问：规划决策、线控执行与车载网络

本篇迁移自动驾驶系列第二批 10 道问答（原题 12–21），覆盖轻地图、全局/局部规划、规则与学习决策、Frenet 坐标、线控转向/制动、功能安全、车载以太网、TSN 和 SOME/IP/DDS。

11. 为什么量产自动驾驶越来越强调轻地图或无图？

答案： 高精地图需要采集、制作、更新和合规管理，成本高、更新周期长、覆盖扩张慢。随着车端感知、在线建图和数据闭环能力增强，系统可以降低对高精地图的依赖。

但“无图”通常不是完全没有地图：导航拓扑、道路先验或记忆地图仍可能存在。合理方向是按功能需求选择地图信息，避免把“轻地图”误解为不再需要道路先验。

12. 全局路径规划、行为决策和局部轨迹规划如何分工？

答案：

  • 全局路径规划：根据起终点和道路拓扑决定走哪些道路/路口。
  • 行为决策：决定当前执行跟车、变道、超车、让行、停车等哪种行为。
  • 局部轨迹规划：根据实时感知、自车状态和行为目标生成未来数秒可执行的轨迹点/速度曲线。
flowchart LR
  A[全局路径 Route] --> B[行为决策 Behavior]
  B --> C[局部轨迹 Motion]
  D[导航地图] --> A
  E[交通规则 / 场景理解] --> B
  F[实时感知 / 障碍物 / 自车状态] --> C
  C --> G[车辆控制]

13. 量产行为决策为什么常采用规则与学习结合？

答案： 规则/状态机具有可解释、可复现、易验证和边界可控等优点；学习方法在复杂交互、长尾场景和行为泛化方面有潜力，但需要大量数据、严格评估和安全约束。工程上常见做法是用规则定义安全边界与关键行为约束，让学习模型提供感知、预测或候选行为，再由安全监控层兜底。

这不是说学习方法无法量产，而是安全关键功能需要可论证的风险控制、验证覆盖和失效策略。

14. 轨迹规划为什么常用 Frenet 坐标系？

答案： Frenet 坐标以道路参考线为基准，s 表示沿参考线的纵向弧长，d 表示横向偏移。它把道路结构化问题拆成纵向速度/跟车和横向换道/避让，便于表达车道边界与舒适性约束。

局限是依赖可靠参考线；在非结构化道路、停车场或极大曲率区域，坐标变换可能不稳定，需要切换或结合笛卡尔坐标规划。

flowchart LR
  A[道路中心线] --> B[Frenet 坐标 s / d]
  B --> C[纵向规划：速度 / 跟车]
  B --> D[横向规划：车道 / 换道]
  C --> E[组合轨迹]
  D --> E
  E --> F[转换回车辆坐标系]

15. 线控转向为什么需要 fail-operational 冗余？

答案： 转向失效可能直接导致车辆失去横向控制能力，因此系统需要在特定故障后仍能维持规定功能，或进入安全可控的降级状态。冗余可能包括双绕组电机、双控制器、双传感器、双供电/通信、故障监控与切换，以及部分架构中的机械备份。

“Fail-operational”是安全目标和架构要求，不代表简单堆叠两套硬件就自动满足；还要分析共因失效、故障检测时间、切换瞬态和故障后的可控性。

16. 线控制动比传统液压制动快在哪里？为什么响应时间重要？

答案： 线控制动通过电信号驱动电机/电液执行器建立制动力，便于精确调节和与 AEB、ABS、ESC、再生制动协同。响应延迟减少可缩短制动开始前的行驶距离。

例如车辆以 100 km/h（约 27.8m/s）行驶，响应延迟减少 100ms，在开始减速前可少行驶约 2.78m。该估算只反映延迟阶段的行驶距离差，不等于最终制动距离必然减少同样数值。

17. 为什么转向和制动执行层常需要很高的 ASIL 目标？

答案： HARA 依据伤害严重度 S、暴露概率 E 和可控性 C 等因素评估危险事件并确定 ASIL。转向/制动执行器直接影响车辆运动，某些失效场景后果严重且驾驶员可能难以控制，因此相关安全目标可能达到高 ASIL。

但 ASIL 不是按“模块层级”自动分配。必须针对具体危险事件、运行场景和安全目标开展 HARA；不能笼统断言所有执行层都必然是 ASIL D。

18. 自动驾驶为什么需要车载以太网？CAN 会被完全取代吗？

答案： 摄像头、激光雷达和域控制器之间的数据量远高于传统控制信号，车载以太网提供更高带宽、交换式拓扑和 IP 生态，适合高速骨干网络与服务化通信。CAN/CAN FD 仍适合大量低速、短报文控制和成熟 ECU 网络；LIN 仍适合低成本车身节点。

因此常见架构是“以太网做高速骨干，CAN/LIN 保留在边缘”，而不是把 CAN 全面淘汰。

flowchart TD
  A[车载网络] --> B[高速骨干：Ethernet]
  A --> C[控制网络：CAN / CAN FD]
  A --> D[低成本节点：LIN]
  B --> E[域控制器 / 中央计算 / 传感器数据]
  C --> F[底盘 / 车身 / 动力控制]
  D --> G[门窗 / 座椅等节点]

19. TSN 解决了标准以太网的什么问题？

答案： 标准以太网通常按尽力而为方式转发，流量竞争可能导致延迟和抖动变化。TSN 通过时间同步、流量整形、时隙调度、帧抢占和资源预留等机制，为关键流量提供更可控的时延和抖动边界。

TSN 不是“所有报文零延迟”，也不是只配置一个 Qbv 就自动获得端到端确定性；还需考虑端系统、交换机、时钟误差、队列、流量模型和故障场景。

20. SOME/IP 和 DDS 分别适合什么场景？

答案：

维度SOME/IPDDS
通信模型面向服务：请求/响应、事件数据中心：发布/订阅 Topic
主要特点车载 SOA、服务发现、生态集成丰富 QoS、动态发现、数据分发
常见场景AUTOSAR Adaptive 车载服务ROS 2、机器人和复杂分布式系统
选择重点服务契约、车规集成、资源预算QoS、实时数据流、节点规模和互操作

两者并非绝对互斥，具体可按系统边界、平台支持和网络部署组合使用。

工程验证清单

  • 轻地图：检查道路拓扑先验与实时感知不一致时的降级策略。
  • 规划：分别验证 Route、Behavior、Motion 的接口边界和重规划频率。
  • Frenet：测试参考线跳变、急弯、合流和非结构化道路。
  • 线控执行：故障注入验证双通道切换、共因失效和降级响应。
  • 车载以太网：测量端到端延迟、丢包、抖动、带宽和 TSN 时钟同步。
  • SOME/IP/DDS：验证服务发现、QoS、网络分区和故障恢复。
